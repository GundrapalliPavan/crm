# Coding Standards

**Project:** CRM Platform **Document:** 12_Coding_Standards.md
**Version:** 1.0

------------------------------------------------------------------------

# Purpose

This document defines the engineering standards, coding conventions,
quality requirements, and development practices for the CRM Platform.

These standards apply to the backend, frontend, mobile application,
database, infrastructure, and automated code generated by Claude Code.

------------------------------------------------------------------------

# Core Principles

-   Readability over cleverness
-   Consistency over personal preference
-   Composition over duplication
-   Security by default
-   Performance by design
-   Testability first
-   Documentation is part of development

------------------------------------------------------------------------

## Backend

-   NestJS
-   TypeScript (strict mode)
-   Prisma
-   PostgreSQL

## Frontend

-   Next.js App Router
-   TypeScript
-   Tailwind CSS
-   shadcn/ui
-   TanStack Query

## Mobile

-   React Native
-   Expo
-   TypeScript

------------------------------------------------------------------------

# Folder Structure

Follow the approved architecture documents.

Do not introduce new top-level folders without architectural approval.

------------------------------------------------------------------------

# Naming Conventions

## Files

-   kebab-case.ts
-   user.service.ts
-   lead.repository.ts

## Classes

PascalCase

Example:

-   UserService
-   LeadController

## Variables

camelCase

## Constants

UPPER_SNAKE_CASE

## Database

-   snake_case tables
-   snake_case columns

## Prisma

-   PascalCase models
-   camelCase fields
-   @@map() for table names
-   @map() for column names

------------------------------------------------------------------------

# TypeScript Standards

-   Enable strict mode.
-   Avoid any.
-   Prefer interfaces for contracts.
-   Prefer enums only where appropriate.
-   Use readonly when possible.

------------------------------------------------------------------------

# Backend Standards

Controllers

-   Validate requests
-   Return responses
-   Never implement business logic

Services

-   Business rules
-   Transactions
-   Domain validation

Repositories

-   Database access only

DTOs

-   Validation
-   Transformation

------------------------------------------------------------------------

# Frontend Standards

Components

-   Small
-   Reusable
-   Presentation focused

Business logic belongs in:

-   hooks
-   services

Never inside UI components.

------------------------------------------------------------------------

# React Standards

-   Functional components only
-   Custom hooks for reusable logic
-   Avoid prop drilling
-   Prefer composition

------------------------------------------------------------------------

# API Standards

-   REST
-   JSON
-   Versioned
-   Consistent responses

No breaking changes in the same API version.

------------------------------------------------------------------------

# Error Handling

Use centralized error handling.

Never expose:

-   Stack traces
-   Database errors
-   Internal implementation details

------------------------------------------------------------------------

# Logging

Log:

-   Authentication
-   Business events
-   Errors
-   Audit events

Never log:

-   Passwords
-   Tokens
-   Sensitive personal information

------------------------------------------------------------------------

# Security

-   JWT
-   RBAC
-   Input validation
-   Output encoding
-   Rate limiting
-   HTTPS only
-   Secure headers

Secrets must be stored in environment variables.

------------------------------------------------------------------------

# Database Standards

-   UUID primary keys
-   Foreign keys
-   Transactions
-   Soft deletes
-   Indexed foreign keys

Never use raw SQL unless justified.

------------------------------------------------------------------------

# Testing

Unit Tests

-   Services
-   Utilities

Integration Tests

-   APIs
-   Repositories

E2E Tests

-   Critical business workflows

Coverage target:

-   Minimum 80%

------------------------------------------------------------------------

# Git Standards

Branch naming

-   feature/\*
-   bugfix/\*
-   hotfix/\*
-   release/\*

Commit format

-   feat:
-   fix:
-   refactor:
-   docs:
-   test:
-   chore:

------------------------------------------------------------------------

# Pull Requests

Every PR must include:

-   Description
-   Screenshots (UI changes)
-   Test results
-   Related issue
-   Breaking changes (if any)

------------------------------------------------------------------------

# Performance

-   Optimize queries
-   Lazy loading
-   Pagination
-   Avoid N+1 queries
-   Cache master data

------------------------------------------------------------------------

# Accessibility

Follow WCAG AA.

Support:

-   Keyboard navigation
-   Screen readers
-   Focus states
-   Semantic HTML

------------------------------------------------------------------------

# Documentation

Every module must include:

-   README
-   API documentation
-   Business rules
-   Setup instructions (if needed)

------------------------------------------------------------------------

# Definition of Done

A feature is complete only when:

-   Requirements implemented
-   Tests pass
-   Documentation updated
-   Code reviewed
-   Security reviewed
-   Performance verified
-   No lint errors
-   No TypeScript errors

------------------------------------------------------------------------

# Code Review Checklist

-   Correct architecture
-   No duplicated logic
-   Proper error handling
-   Validation implemented
-   Authorization enforced
-   Tests included
-   Naming conventions followed
-   Performance considered

------------------------------------------------------------------------

# Claude Code Instructions

-   Follow these standards for every generated file.
-   Never duplicate existing functionality.
-   Reuse shared utilities and components.
-   Keep modules cohesive and loosely coupled.
-   Prefer maintainability over shorter code.
-   Generate production-ready, well-documented code.
